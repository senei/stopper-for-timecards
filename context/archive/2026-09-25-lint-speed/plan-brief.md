# Lint Speed — Plan Brief

> Full plan: `context/changes/lint-speed/plan.md`
> Research: `context/changes/lint-speed/research.md`

## What & Why

Lint is slow to run, and the measurements show one avoidable cause: a 15,384-line, Wrangler-generated file (`workers/purge-job/worker-configuration.d.ts`) that ESLint and Prettier process on every run. About half of the measured lint time goes to it, even though its own `eslint-disable` header cannot stop the rules from running. The plan ignores it in both tools and proves the saving with matched before/after timings.

## Starting Point

`npm run lint` lints about 47 files with type-aware rules and Prettier inside ESLint; a full uncached run took 33 s on this machine in the primary checkout. There is no `.prettierignore`, and the generated file is tracked in git and regenerated by hand (it has been committed twice). The much slower cold runs seen in fresh worktrees (4 to 15 minutes) are unexplained and are not addressed here.

## Desired End State

ESLint and Prettier both skip `worker-configuration.d.ts`; the file stays tracked and untouched; `npm run lint` still exits 0 with no problems. `measurements.md` in the change folder shows three timed runs before and three after, with a strictly lower median after.

## Key Decisions Made

| Decision | Choice | Why (1 sentence) | Source |
| --- | --- | --- | --- |
| Generated file | Ignore in ESLint and a new `.prettierignore`; keep it tracked | Measured 33 s to 20 s with no workflow change, and it also covers `npm run format` and the commit hook. | Plan (user-confirmed) |
| Cold-start slowness | Separate change | It is untested, and the fix should not wait on it. | Plan (user-confirmed) |
| What counts as "faster" | Median of 3 timed uncached runs, before vs after, strictly lower | Single timings here ranged from 33 s to 253 s, so one pair proves nothing. | Plan (user-confirmed) |
| Ignore pattern | `**/worker-configuration.d.ts` | Wrangler uses that name for every worker's generated types. | Plan |
| Timed command | `node node_modules/eslint/bin/eslint.js . --no-cache` after one discarded warm-up | Avoids about 9 s of `npx` start-up and the cache, and absorbs first-run effects. | Research |
| Commit hook | No change needed | ESLint on an explicitly passed ignored file warns and exits 0 (tested). | Research + tested |

## Scope

**In scope:**
- An ignore entry in `eslint.config.js` and a new `.prettierignore`
- Baseline and after measurements recorded in `measurements.md`

**Out of scope:**
- Investigating cold-start slowness (separate change)
- Untracking the generated file or adding a `wrangler types` step
- Removing Prettier-in-ESLint, dropping type-aware rules, CI or machine-level changes
- A fixed time target

## Architecture / Approach

Measure first, then change, then measure again in the same checkout with the same command. The change is two ignore entries. Prettier 3 reads `.gitignore` and `.prettierignore` by default, so a check confirms gitignored paths such as `dist/` are still ignored after adding the new file.

## Phases at a Glance

| Phase | What it delivers | Key risk |
| --- | --- | --- |
| 1. Baseline | Three timed uncached lints and their median in `measurements.md` | Run-to-run noise on a shared machine (a first run once took 253 s) |
| 2. Ignore and re-measure | The two ignore entries, both tools confirmed ignoring the file, three timed runs after, and the comparison | A new `.prettierignore` accidentally dropping gitignore-based ignores |

**Prerequisites:** none; the primary checkout already has `node_modules` and `.astro/`.
**Estimated effort:** about 1 session across 2 phases, dominated by the six timed runs (roughly a minute each).

## Open Risks & Assumptions

- The 13 s saving comes from one run each; the median-of-3 comparison exists to confirm or refute it.
- Timings depend on a quiet machine; other sessions running builds or dev servers can distort them.
- The change folder is currently uncommitted on `main`; commit it or carry it into the implementation worktree first.

## Success Criteria (Summary)

- Both ESLint and Prettier report the generated file as ignored, and gitignored paths are still ignored
- `npm run lint` exits 0 with no problems
- The after-median of three full uncached runs is strictly lower than the baseline median
